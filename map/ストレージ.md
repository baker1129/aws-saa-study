# ストレージの地図

> **試験ドメイン対応**
> - Domain 1（セキュリティ 30%）: S3暗号化（SSE-S3/SSE-KMS/SSE-C）、バケットポリシー
> - Domain 3（パフォーマンス 24%）: EBSタイプ選択、S3パフォーマンス
> - Domain 4（コスト最適化 20%）: S3ストレージクラス、ライフサイクルポリシー

## なぜ複数のストレージがあるのか

「何を、どこから、どう使うか」で最適なストレージが変わる。

```
         ブロック     ファイル    オブジェクト
         （EBS）      （EFS）       （S3）

イメージ  HDDをつける  NASを共有    URLでアクセスするクラウドストレージ
アクセス  EC2から直接  複数EC2から  HTTPで誰でも（権限次第）
用途      OSディスク   共有ファイル 画像・ログ・バックアップ
```

---

## S3（Simple Storage Service）

**なぜ存在するか**: ファイルを無制限に・安く・高耐久に保存したいから。

**特徴**:
- 容量制限なし（1ファイル最大5TB）
- 耐久性: イレブン・ナイン（99.999999999%）
- HTTPSでアクセス（EC2に接続不要）

**ストレージクラス（コスト最適化に直結）**:
| クラス | 用途 | 取り出し |
|---|---|---|
| Standard | 頻繁にアクセス | 即座 |
| Standard-IA | 月1回程度のアクセス | 即座（取り出し料金あり） |
| One Zone-IA | アクセス少・消えても再作成できる | 即座 |
| Glacier Instant | アーカイブ・たまに取り出す | 即座 |
| Glacier Flexible | アーカイブ・ほぼ取り出さない | 数分〜数時間 |
| Glacier Deep Archive | 長期保存・ほぼ取り出さない | 12時間 |
| Intelligent-Tiering | アクセスパターン不明 | 自動で最適化 |

**試験で問われる判断**:
- 古いデータを自動でGlacierへ → `ライフサイクルポリシー`
- 削除・上書きを防ぎたい → `バージョニング` + `MFADelete`
- オブジェクトを変更不可にしたい → `Object Lock`（WORM）
- 静的ウェブサイトを公開したい → `Static Website Hosting`

---

## EBS（Elastic Block Store）

**なぜ存在するか**: EC2にHDD/SSDを「追加する」ため。

**特徴**:
- EC2の「ディスク」として機能
- 1つのEBSは原則1つのEC2にしかアタッチできない
- EC2を停止してもデータは消えない（インスタンスストアは消える）

**ボリュームタイプ**:
| タイプ | 特徴 | 用途 |
|---|---|---|
| gp3 | 汎用SSD（最新・推奨） | 一般的なワークロード |
| gp2 | 汎用SSD（旧） | 同上（gp3が上位互換） |
| io2 Block Express | 高性能SSD | DBなど高IOPS要件 |
| st1 | スループット最適化HDD | ビッグデータ・ログ処理 |
| sc1 | コールドHDD | アクセス頻度低・安価 |

**試験で問われる判断**:
- EC2を停止してもデータ維持 → EBS（インスタンスストアではない）
- 複数EC2から同時にアタッチ → EBSではなくEFS
- スナップショット → S3に保存される（EBSのバックアップ）

---

## EFS（Elastic File System）

**なぜ存在するか**: 複数のEC2から同じファイルシステムを共有するため。

**特徴**:
- NFS（Network File System）プロトコル
- 複数EC2・複数AZから同時にマウント可能
- 自動でスケール（容量を事前に決めなくていい）
- EBSより高価

**試験で問われる判断**:
- 「複数のEC2が同じファイルを読み書き」→ EFS
- Windowsファイル共有（SMB） → FSx for Windows

## よく試験に出る比較

### S3 vs EBS vs EFS
| | S3 | EBS | EFS |
|---|---|---|---|
| アクセス方法 | HTTP/HTTPS | EC2から直接 | NFS（複数EC2） |
| スケール | 無制限・自動 | 事前に確保 | 自動 |
| コスト | 安い | 中程度 | 高め |
| 用途 | ファイル保管 | OSディスク | 共有ファイル |

### インスタンスストア vs EBS
| | インスタンスストア | EBS |
|---|---|---|
| EC2停止後 | データ消える | データ残る |
| 速度 | 非常に高速 | 高速 |
| 用途 | 一時的な高速キャッシュ | 永続データ |
