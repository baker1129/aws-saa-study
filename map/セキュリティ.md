## IAM（Identity and Access Management）

**なぜ存在するか**: 「誰がAWSの何を操作できるか」を管理するため。

**重要な概念**:
| 概念 | 説明 |
|---|---|
| ユーザー | 個人に紐づくアカウント |
| グループ | ユーザーをまとめる単位。グループにポリシーを付与 |
| ロール | AWSサービス・アプリに一時的な権限を付与する仕組み |
| ポリシー | 「何ができるか」を定義したJSON文書 |

**ロールが重要な理由**:
- EC2がS3にアクセスする → EC2にロールをアタッチ（アクセスキーを使わない）
- Lambda がDynamoDBにアクセスする → Lambdaのロールに権限を付与
- アクセスキーは漏洩リスクがあるため、サービス間はロールを使うのがベストプラクティス

**試験で問われる判断**:
- 「最小権限の原則」→ 必要最小限の権限だけを付与
- クロスアカウントアクセス → ロールの信頼ポリシーを使う
- 「アクセスキーをコードに書いた」→ 問題あり。ロールを使うべき

## Cognito

**なぜ存在するか**: アプリのユーザー認証（ログイン機能）をサービスとして提供するため。

| コンポーネント | 役割 |
|---|---|
| User Pool | ユーザーの登録・ログイン管理（メール/SNSログイン） |
| Identity Pool | AWSリソースへの一時的なアクセス権限を付与 |

**試験で問われる判断**:
- 「モバイルアプリのユーザー認証」→ Cognito User Pool
- 「ログインしたユーザーにS3へのアクセス権を与えたい」→ Cognito Identity Pool
- IAMとCognito の違い → IAMはAWSサービスの操作者管理、CognitoはアプリのエンドユーザーのID管理

## KMS（Key Management Service）

**なぜ存在するか**: 暗号化キーを安全に管理・使用するため。

**特徴**:
- S3, EBS, RDS, DynamoDBなどのデータ暗号化に使われる
- キーのローテーション自動化が可能
- CloudTrailで全キー使用のログが取れる（監査に重要）

**暗号化の種類**:
- `サーバーサイド暗号化（SSE）`: AWS側で暗号化
  - SSE-S3: S3管理キー
  - SSE-KMS: KMSキー（誰がいつ使ったか追跡可能）
  - SSE-C: 自分でキーを持ち込む
- `クライアントサイド暗号化`: AWSに送る前にアプリ側で暗号化

**試験で問われる判断**:
- 「暗号化キーの使用履歴を監査したい」→ SSE-KMS
- 「自社でキーを管理したい」→ SSE-C または CloudHSM

## Secrets Manager vs Parameter Store

| | Secrets Manager | SSM Parameter Store |
|---|---|---|
| 主な用途 | DBパスワード等のシークレット管理 | 設定値・パラメータ管理 |
| 自動ローテーション | あり（RDS等と自動連携） | なし |
| コスト | 有料（シークレット単位） | 無料（標準パラメータ） |

**試験で問われる判断**:
- 「DBのパスワードを自動ローテーションしたい」→ Secrets Manager
- 「設定値をアプリに渡したい」→ Parameter Store

## WAF・Shield（攻撃防御）

| サービス | 防ぐもの | 設置場所 |
|---|---|---|
| WAF | SQLインジェクション、XSS、特定IPブロック | CloudFront, ALB, API Gateway |
| Shield Standard | 一般的なDDoS攻撃 | 自動（全ユーザー無料） |
| Shield Advanced | 高度なDDoS攻撃 + 24時間対応 | 有料（大規模サイト向け） |

## 検知・監視系

| サービス | 役割 |
|---|---|
| GuardDuty | 不審なAPIコール・ネットワーク通信を機械学習で検知 |
| Inspector | EC2・コンテナの脆弱性スキャン |
| Security Hub | 複数のセキュリティサービスの結果を一元集約 |
| CloudTrail | 全AWSAPIコールのログ（「誰が何をいつやったか」） |
| Config | AWSリソースの設定変更履歴と準拠チェック |

**試験で問われる判断**:
- 「誰がS3のバケットを削除したか調べたい」→ CloudTrail
- 「EC2に不審なリクエストが来ていないか」→ GuardDuty
- 「セキュリティポリシーに違反した設定変更を検知したい」→ Config
