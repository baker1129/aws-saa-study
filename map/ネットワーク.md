# ネットワークの地図

> **試験ドメイン対応**
> - Domain 1（セキュリティ 30%）: Security Group vs NACL、VPCエンドポイント、PrivateLink
> - Domain 2（回復性 26%）: マルチAZ、Route53フェイルオーバー
> - Domain 3（パフォーマンス 24%）: CloudFront、Global Accelerator
> - Domain 4（コスト最適化 20%）: NAT Gatewayコスト、VPCエンドポイントでコスト削減

## 全体像：AWSのネットワーク構造

```
インターネット
    │
    ▼
Internet Gateway  ← VPCをインターネットに繋ぐ玄関口
    │
    ▼
[VPC（仮想ネットワーク）]
    ├── パブリックサブネット（外からアクセス可）
    │       └── ALB, EC2, NAT Gateway など
    │
    └── プライベートサブネット（外からアクセス不可）
            └── RDS, Lambda, EC2（バックエンド）など
```

## VPC（Virtual Private Cloud）

**なぜ存在するか**: AWS上に「自分専用のネットワーク」を作るため。

**重要な概念**:

| 概念 | 役割 |
|---|---|
| VPC | 仮想ネットワーク全体。自分でIPアドレス範囲（CIDR）を決める |
| サブネット | VPCをさらに分割した区画。AZをまたがない |
| Internet Gateway | VPCとインターネットを繋ぐ。パブリックサブネットに必要 |
| NAT Gateway | プライベートサブネットのEC2が外（インターネット）に出るための出口 |
| ルートテーブル | 「どこへの通信をどこに転送するか」のルール |
| Security Group | EC2などへのインバウンド/アウトバウンドをポート単位で制御（ステートフル） |
| Network ACL | サブネット単位のアクセス制御（ステートレス） |

**試験で問われる判断**:
- 「EC2がインターネットに出られない」→ NAT Gatewayの設定を確認
- 「外からアクセスできない」→ Internet Gateway とパブリックIPの確認
- Security Group vs NACL → セキュリティグループはステートフル（戻りの通信を自動許可）、NACLはステートレス（戻りも明示的に許可が必要）

## ロードバランサー（ELB）

**なぜ存在するか**: 複数のサーバーにリクエストを分散させるため。

| タイプ | レイヤー | 向いてる用途 |
|---|---|---|
| ALB（Application LB） | L7（HTTP/HTTPS） | Webアプリ、パスベースルーティング |
| NLB（Network LB） | L4（TCP/UDP） | 高速・低レイテンシ、固定IP必要 |
| CLB（Classic LB） | L4/L7 | 旧世代（試験でも「使わない理由」で出る） |

**試験で問われる判断**:
- パスによる振り分け（/api → Aサーバー、/web → Bサーバー）→ ALB
- 固定IPアドレスが必要 → NLB
- WebSocket → ALB または NLB

## CloudFront

**なぜ存在するか**: コンテンツをユーザーの近くのサーバー（エッジロケーション）からキャッシュ配信するため。

**特徴**:
- 世界中にエッジロケーション（450+）
- S3, ALB, EC2, API Gatewayなど様々なオリジンに対応
- HTTPSの終端もここで行える
- WAFと組み合わせてセキュリティ強化

**試験で問われる判断**:
- 「世界中のユーザーに速く配信」→ CloudFront
- 「S3の静的コンテンツを速く配信」→ CloudFront + S3
- 「特定の国からのアクセスをブロック」→ CloudFront の地理的制限

## Route 53

**なぜ存在するか**: ドメイン名をIPアドレスに変換するDNSサービス。

**ルーティングポリシー**（試験頻出）:
| ポリシー | 用途 |
|---|---|
| Simple | 単純に1つのIPへ転送 |
| Weighted | 重み付きで複数リソースに分散（A:70%, B:30% など） |
| Latency | レイテンシが最も低いリージョンへ転送 |
| Failover | ヘルスチェック失敗時に別リソースへ切り替え |
| Geolocation | ユーザーの地理的場所に基づいてルーティング |
| Geoproximity | 地理的近さ + バイアス値でルーティング |
| Multivalue | 複数の正常なIPを返す（簡易ロードバランシング） |

**試験で問われる判断**:
- 「別リージョンへのフェイルオーバー」→ Failoverポリシー + ヘルスチェック
- 「A/Bテスト」→ Weightedポリシー
- 「ユーザーに最も近いリージョン」→ Latencyポリシー

## オンプレミス接続

| サービス | 特徴 | 向いてる用途 |
|---|---|---|
| Site-to-Site VPN | インターネット経由の暗号化トンネル | 低コスト・すぐ繋ぎたい |
| Direct Connect | 専用物理回線 | 高帯域・安定・低レイテンシが必要 |
| VPN + Direct Connect | Direct Connectのバックアップにも | 冗長化 |

## VPCピアリング vs Transit Gateway

| | VPCピアリング | Transit Gateway |
|---|---|---|
| 繋ぐVPCの数 | 1対1 | 多対多（ハブ型） |
| トランジットルーティング | 不可（A→B→CはA→C不可） | 可能 |
| 向いてる規模 | 少数のVPC間接続 | 多数のVPC・オンプレ接続 |
