# Well-Architected Framework の地図 — 6本の柱

> **試験での位置づけ**
> これは特定サービスの話ではなく、SAA全体を貫く「設計の良し悪しを測るモノサシ」。
> 4つの試験ドメイン（セキュリティ / 回復性 / パフォーマンス / コスト最適化）は、
> この6本の柱とほぼ対応している。だから6本を押さえると、ドメイン全体の見通しが効く。

## これは何か（1行で）

**「良いシステムってこういうものだよね」を AWS が6項目にまとめた、設計の通信簿。**

なぜ存在するか → その場の思いつきで設計すると、必ず抜け漏れ（守り忘れ・ムダ・遅さ）が出るから。
共通のチェック項目を持っておけば「ここ抜けてない?」と毎回見直せる。

試験で問われるのは「このサービスは何か」ではなく、**「この場面でどの柱を優先する設計か」**。

---

## たとえ：レストランを作って、ずっと繁盛させる

クラウドのシステムを「お店（レストラン）」だと思う。
お客さん（= ユーザー）に来てもらって、ずっと繁盛させたい。
そのために気をつける6つのこと、それが6本の柱。

覚えやすいように **3つのペア** に分ける。

```
🛡 守る系          ⚙️ うまく動かす系       💰 ムダをなくす系
（こわれない・      （ちゃんと回す・        （お金・地球）
  とられない）        速くする）
─────────────     ─────────────       ─────────────
① セキュリティ      ③ 運用上の優秀性        ⑤ コスト最適化
② 信頼性            ④ パフォーマンス効率     ⑥ 持続可能性
```

---

## 🛡 守る系 — こわれない・とられない

### ① セキュリティ（Security）
- **子どもの一言**：「どろぼうに入られないようにする」
- **お店のたとえ**：鍵をかける、金庫にしまう、誰がどの部屋に入れるか決める
- **なぜ存在するか**：守らないと、データを盗まれる・壊される
- **試験キーワード**：`暗号化` `最小権限` `MFA` `データ保護` `KMS` `IAM`

### ② 信頼性（Reliability）
- **子どもの一言**：「こわれても、お店を止めない」
- **お店のたとえ**：コンロが1個こわれても別ので作れる。停電しても予備電源。お客が急に増えても回せる
- **なぜ存在するか**：1台壊れただけでサービス全部が止まると困る
- **試験キーワード**：`高可用性` `マルチAZ` `自動復旧` `フェイルオーバー` `ダウンタイム最小`

---

## ⚙️ うまく動かす系 — ちゃんと回す・速くする

### ③ 運用上の優秀性（Operational Excellence）
- **子どもの一言**：「毎日のまわし方を、どんどん良くする」
- **お店のたとえ**：マニュアルを作る、異変にすぐ気づく仕組み、失敗から学んで改善
- **なぜ存在するか**：その場しのぎの運用だと、同じ失敗を繰り返す
- **試験キーワード**：`監視` `自動化` `CloudWatch` `IaC（CloudFormation）` `手順の改善`

### ④ パフォーマンス効率（Performance Efficiency）
- **子どもの一言**：「ちょうどいい大きさ・速さにする」
- **お店のたとえ**：お客の数にちょうど合った席数・人数。大きすぎず小さすぎず、待たせない
- **なぜ存在するか**：遅いとお客が離れる。逆に過剰でもムダ
- **試験キーワード**：`適切なリソース選択` `スケーリング` `キャッシュ（CloudFront / DAX / ElastiCache）`

---

## 💰 ムダをなくす系 — お金・地球

### ⑤ コスト最適化（Cost Optimization）
- **子どもの一言**：「いらないお金を使わない」
- **お店のたとえ**：使ってない部屋の電気は消す。食材は必要な分だけ。使った分だけ払う
- **なぜ存在するか**：払わなくていいお金を払い続けてしまう
- **試験キーワード**：`従量課金` `適正サイズ（Right Sizing）` `不要リソース削除` `RI / スポット / Savings Plans`

### ⑥ 持続可能性（Sustainability）
- **子どもの一言**：「地球にやさしくする」
- **お店のたとえ**：省エネ、ムダな電気を使わない、ゴミを減らす
- **なぜ存在するか**：クラウドの利用にも環境負荷がある。それを最小化する
- **試験キーワード**：`環境負荷の最小化` `リソースの無駄を減らす`（最後に追加された一番新しい柱）

---

## 試験で効く「混同しやすい所」

ここだけ子どもの言葉で区別できれば強い。

| 迷いやすいペア | 見分け方（問題文のどこを見るか） |
|---|---|
| 信頼性 vs パフォーマンス効率 | **止まる・こわれる・ダウンタイム** → 信頼性 / **遅い・待たされる** → パフォーマンス |
| コスト最適化 vs パフォーマンス効率 | どちらも「適正サイズ」を言うが、**お金が主役** → コスト / **速さ・体験が主役** → パフォーマンス |
| 運用上の優秀性 vs 信頼性 | **改善・監視・手順** → 運用 / **壊れても生き残る** → 信頼性 |

## 理解の確認（ノートを閉じて言えるか）

```

3ペアで覚える：守る系（セキュリティ・信頼性）／
うまく動かす系（運用・パフォーマンス）／ムダなくす系（コスト・持続可能性）。
試験では「この場面でどの柱を優先するか」を問われる。
```
