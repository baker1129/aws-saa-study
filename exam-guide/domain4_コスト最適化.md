# Domain 4: コスト最適化されたアーキテクチャの設計（20%）

「必要な分だけ、適切な方法で使う」設計。
キーワード: 適切なサービス選択、使い方の最適化、不要リソースの削除

---

## コスト最適化の考え方

試験ではコスト問題は単独で出るだけでなく、**他の要件（可用性・パフォーマンス）を満たしながらコストも下げる**という形で出ることが多い。

「最も安い」だけでなく「要件を満たした上で最もコストを最小化する」を意識する。

---

## タスク4.1: コスト最適化されたストレージを設計する

### S3 のコスト最適化

**ストレージクラスの選択**（アクセス頻度で選ぶ）
```
頻繁にアクセス    → Standard
月1回程度         → Standard-IA（取り出し料金あり）
ほぼアクセスしない → Glacier Flexible / Deep Archive
アクセスパターン不明 → Intelligent-Tiering（自動最適化）
```

**ライフサイクルポリシー**
- 日数が経過したら自動でストレージクラスを変更
- 例: 作成から30日→Standard-IA、90日→Glacier、365日→削除

**試験でよく出るパターン**:
- 「古いログを安く保存したい」→ ライフサイクルポリシーでGlacierへ移行
- 「いつアクセスされるか予測できない」→ Intelligent-Tiering
- 「コンプライアンスで7年保存が必要」→ Glacier Deep Archive

### EBS のコスト最適化

- 不要なスナップショットを削除する
- gp2 から gp3 へ移行（同性能でコスト削減）
- 使っていないEBSボリュームを削除

## タスク4.2: コスト最適化された計算リソースを設計する

### EC2 の購入オプション

| 購入オプション | 割引 | 条件 | 向いてる用途 |
|---|---|---|---|
| オンデマンド | なし | なし | 短期・予測困難な負荷 |
| リザーブドインスタンス | 最大72% | 1〜3年のコミット | 常時稼働・安定した負荷 |
| Savings Plans | 最大66% | 1〜3年のコミット（柔軟） | EC2・Lambda・Fargate横断 |
| スポットインスタンス | 最大90% | 中断される可能性あり | バッチ処理・耐障害性ある処理 |
| 専有ホスト | — | 物理ホストを占有 | ライセンス要件・コンプライアンス |

**リザーブドインスタンス vs Savings Plans**
- Savings Plans の方が柔軟（インスタンスタイプ・リージョンをまたいで適用）
- 新規では Savings Plans が推奨されることが多い

**試験でよく出るパターン**:
- 「24時間365日動くWebサーバーを安くしたい」→ リザーブドインスタンス or Savings Plans
- 「週末だけ動く処理を安くしたい」→ スポットインスタンス or Lambda
- 「中断されてもよい大規模バッチ処理」→ スポットインスタンス

### サーバーレスでコスト削減

- 常時稼働が不要なら Lambda + API Gateway の方が安いことが多い
- EC2は停止中もEBSやEIPのコストが発生する点に注意

## タスク4.3: コスト最適化されたデータベースを設計する

### RDS のコスト最適化

- 開発・テスト環境 → マルチAZは不要
- リザーブドインスタンス → 1〜3年コミットで最大60%割引
- Aurora Serverless v2 → アクセスがないときコストほぼゼロ

### DynamoDB のコスト最適化

| モード | 向いてる状況 |
|---|---|
| オンデマンド | アクセスが予測できない・新規サービス |
| プロビジョンド | アクセスが安定している（+ Auto Scaling で調整） |

## タスク4.4: コスト最適化されたネットワークを設計する

### データ転送コストの理解

AWSのコストで見落とされやすいのがデータ転送料金。

- **AZ間の通信**: コストが発生する → 同じAZに配置できないか検討
- **インターネットへのアウトバウンド**: コストが発生する（インバウンドは無料）
- **CloudFrontを使う**: S3から直接配信するよりCloudFront経由の方が安い場合がある
- **NAT Gateway**: プライベートサブネットからのインターネット通信ごとにコスト発生 → VPCエンドポイントでS3・DynamoDBへの通信はコスト削減可能

**試験でよく出るパターン**:
- 「S3へのアクセスのデータ転送コストを削減したい」→ VPCエンドポイント（Gateway型・無料）
- 「CloudFrontを使うとS3の転送コストが下がる」→ CloudFront経由はS3アウトバウンド料金が発生しない
