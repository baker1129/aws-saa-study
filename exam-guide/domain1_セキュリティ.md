# Domain 1: セキュアなアーキテクチャの設計（30%）

出題比率が最も高い。セキュリティは「後から足す」ものではなく「設計に組み込む」もの、という視点が重要。

---

## タスク1.1: AWSリソースへのセキュアなアクセスを設計する

**意識すること**: 「誰が」「何を」「どのように」アクセスするかを制御する。

### 問われる判断

**IAMポリシーの種類**
- `アイデンティティベースポリシー` → ユーザー・ロール・グループにアタッチ
- `リソースベースポリシー` → S3バケット・SQSキュー等のリソース側にアタッチ
- 両方がある場合 → 両方で許可されている操作のみ実行できる

**ロールの使いどころ**
- EC2がS3にアクセス → EC2インスタンスプロファイル（ロール）
- Lambda が DynamoDB にアクセス → Lambda実行ロール
- 別AWSアカウントのユーザーに一時アクセス → クロスアカウントロール
- **アクセスキーをアプリにハードコードするのは常に誤り**

**AWS Organizations と SCP**
- 複数AWSアカウントを一元管理
- SCP（サービスコントロールポリシー）で「このアカウントはEC2しか使えない」等の制限

**試験でよく出るパターン**:
- 「EC2からS3に安全にアクセスしたい」→ IAMロール（アクセスキー不使用）
- 「最小権限を保証したい」→ IAMポリシーで必要な操作のみ許可
- 「複数アカウントで特定サービスの利用を禁止したい」→ SCP

## タスク1.2: セキュアなワークロードとアプリケーションを設計する

**意識すること**: ネットワークの境界でどこを守るか。

### 問われる判断

**VPCのセキュリティ層**
```
インターネット
    ↓
Security Group（インスタンス単位・ステートフル）
    +
Network ACL（サブネット単位・ステートレス）
    ↓
プライベートサブネット内のリソース
```

**VPCエンドポイント**
- インターネットを経由せずAWSサービスにアクセスする仕組み
- `Gateway型`: S3, DynamoDB
- `Interface型（AWS PrivateLink）`: その他ほぼ全サービス
- 「EC2からS3にインターネットを通さずアクセスしたい」→ VPCエンドポイント

**シークレット管理**
- DBパスワードをコードに書かない → `Secrets Manager`
- 自動ローテーションが必要 → `Secrets Manager`
- 設定値（URLなど）を安全に渡したい → `Systems Manager Parameter Store`

**試験でよく出るパターン**:
- 「プライベートサブネットのEC2がS3に安全にアクセス」→ VPCエンドポイント（Gateway）
- 「DBパスワードを安全に管理・自動更新したい」→ Secrets Manager
- 「Web攻撃（SQLi・XSS）を防ぎたい」→ WAF

## タスク1.3: 適切なデータセキュリティコントロールを決定する

**意識すること**: 保存時（at rest）と転送時（in transit）の両方を暗号化する。

### 問われる判断

**保存時の暗号化**
| サービス | 方法 |
|---|---|
| S3 | SSE-S3（デフォルト）/ SSE-KMS（監査可能）/ SSE-C（自前キー） |
| EBS | KMSキーで暗号化（スナップショットも暗号化される） |
| RDS | 作成時に暗号化有効化（後から変更不可・スナップショット経由で変換） |

**転送時の暗号化**
- HTTPS（TLS）を強制する → S3バケットポリシーで `aws:SecureTransport: false` を拒否
- 証明書管理 → ACM（AWS Certificate Manager）

**監査・ログ**
- 「誰が何をいつ操作したか」→ `CloudTrail`（全APIコールのログ）
- 「リソースの設定が変更されたことを検知」→ `AWS Config`
- 「KMSキーの使用履歴を追跡」→ CloudTrail と KMS の組み合わせ

**試験でよく出るパターン**:
- 「S3のデータを暗号化・キーの使用ログを残したい」→ SSE-KMS
- 「RDSの暗号化を有効にしたい（既存DB）」→ スナップショットを取得→暗号化して復元
- 「不正なAPIコールを検知したい」→ CloudTrail + CloudWatch Events（EventBridge）
