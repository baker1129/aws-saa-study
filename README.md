# AWS SAA 学習プロジェクト

## このプロジェクトの考え方

**サービスを覚えるのではなく、「問いに答える力」を育てる。**

SAAが問うのは「このサービスは何か」ではなく「この状況でどれを選ぶか」。  
だから学習の軸を「問い → 判断 → 理由」に置く。

## フォルダ構成

```
map/            ← 地図（Phase 1）今ここ
  全体地図.md       AWSの設計で問われる問いの一覧
  計算リソース.md   EC2 / Lambda / ECS / Fargate の使い分け
  ストレージ.md     S3 / EBS / EFS / FSx の使い分け
  データベース.md   RDS / Aurora / DynamoDB / Redshift 等の使い分け
  ネットワーク.md   VPC / ELB / CloudFront / Route53 等
  セキュリティ.md   IAM / KMS / Cognito / WAF 等

scenarios/      ← シナリオ（Phase 2）
  WebアプリをAWSで作る
  データ分析基盤を作る
  障害に強いシステムを作る ...

exam-patterns/  ← 試験パターン（Phase 3）
  よく出る問題パターンと「なぜその答えか」の解説

labs/           ← ハンズオン（Phase 2以降）
  実際に手を動かすTerraformコード等
```

## 進め方

0. **`読み方ガイド.md` を最初に読む** ← CLFからSAAへの思考の切り替え方がまとめてある
1. `map/全体地図.md` を読んで、SAAで何を判断できればいいかを把握する
2. 各マップファイルを読みながら、「問い → サービス → 理由」を自分の言葉で補足していく
3. 理解が深まったらシナリオで繋げる、試験問題で試す

## 目指す状態

- 問題を読んだとき「何を問われているか」がわかる
- 複数の選択肢を見て「なぜAではなくBか」を説明できる
- 手を動かした経験がある（ただの暗記にならない）
